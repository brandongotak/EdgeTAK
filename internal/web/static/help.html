Getting started

EdgeTAK is a TAK server: ATAK, WinTAK, TAKX and iTAK devices connect to it to share positions, markers, chat, files and video. The console is grouped into sections in the top bar (Dashboard, People, Data, Messages, Server), with each section's pages in the row below.

First steps

  1. Change the admin password: on Users, click Password on admin.
  2. Create groups on Groups, for example Cyan and Command. Devices only see traffic from groups they share.
  3. Create users on Users and tick their groups. Give each person their own user, so you can cut off one device without affecting the rest.
  4. Check the server address: on a local server, packages and QR codes use the address you opened this console at, so open it at the address devices use (not localhost). With Let's Encrypt they use Public host on the Dashboard.
  5. Connect a device: on Connect, make a QR code for a user and scan it with the phone's camera. See Connecting devices.

Tips

  • The map beside every page shows devices live. Map in the top bar shows or hides it.
  • Your own devices, certificates and password are on My account.
  • The theme button in the top bar switches between Auto (your device's light or dark setting), Light and Dark.
  • Every change you make is recorded in the Audit log.

Dashboard

The state of the server at a glance: connected devices, messages, problems that need attention, and updates.

  • Issues at the top list anything wrong: a full disk, certificates about to expire, a federation link down.
  • Server shows the version, the address devices use (Public host) and the ports.
  • EdgeTAK updates: Check for updates, then Install. EdgeTAK restarts itself; devices reconnect on their own. Tick Include pre-releases only on test servers.
  • Connected clients lists every device with its user, groups and connection. You can disconnect one from here.

Health

Graphs of the last hour to 24 hours: CPU, memory, disk, network, temperature (on a Raspberry Pi), connected devices, messages and video bandwidth, with warnings for a full disk, overheating or dropped messages.

The Devices table lists each device's battery (with how fast it drains), last report, GPS fix and connection, worst problems first. Use it to spot a phone about to go flat before it drops off.

Users

Everyone who signs in: people's devices, the console and the account page.

Add a user

  1. Enter a username and a password (8 characters or more).
  2. Tick their groups. No group means __ANON__, shared with anonymous devices.
  3. Tick Administrator only for people who run the server.
  4. Create, then connect their device with QR on their row.

The buttons on each user

  • Groups: which groups, and in which direction: in + out (the usual), in (receive only) or out (send only). Changes reach connected devices at once.
  • Password sets a new one. Make admin / Revoke admin changes their role.
  • Disable cuts them off at once (sign-ins, certificates, connected devices) but keeps the account; Enable brings it all back. Prefer it to Delete.
  • QR makes a QR code that connects their phone (see Connecting devices). Package downloads a connection package; Issue .p12 a certificate for clients set up by hand.
  • Print a QR sheet… (above the list) prints a labelled QR card for each chosen user or a whole group.

Also on this page

  • Two-factor login for your own account: after the password, a code from an authenticator app. TAK apps are not affected.
  • Directory sign-in (LDAP / Active Directory): people sign in with their directory account, and directory groups become EdgeTAK groups. Test these settings before saving.

Groups and device profiles

Groups decide who sees what: a device receives traffic sent to the groups it is in, and its own traffic goes to the groups it is out in. Users can switch groups on and off on their device with ATAK's Channels.

  • Create group with a name and description; members are set on Users or with the group's own button here.
  • Deleting a group removes it from its members.

Device profiles

Settings and files sent to the devices of a group's members (or every user): ATAK settings (key, type and value), .pref files, plugin APKs, map sources and overlays.

  • Devices get them when they set up, and each time they connect if the profile changed.
  • Send now reaches devices that are already connected. Download shows exactly what devices receive.

Events

A temporary operation (a search, an exercise, a race) with its own group and, if you like, a Data Sync mission. People join by scanning one QR code, and everything is cleaned up when it ends.

  1. New event: a name, when it ends, and how people join:
    • Each person signs up: the QR code opens a sign-up page; each person picks a name and gets their own account (limit how many with max people).
    • One shared account: the QR code connects ATAK straight away; every device uses the same account. Fastest for walk-ups.
  2. Show the QR code, or Print a join sheet to post at the check-in point.
  3. When the event ends (at the time you set, or End now), its accounts are erased, their devices disconnected and its group removed. The mission is kept for review.

Extend changes when it ends. Package gets a connection package for the shared account.

Sign-ups

Let people make their own accounts on the sign-up page, instead of creating each one yourself.

  • Invite links: choose the groups, how many people may use it (0 = no limit) and how long it lasts, then share the link or its QR code. Anyone with it gets an account in those groups at once.
  • Sign-up without an invite: Off (invites only, the default), Approval (requests wait under Pending requests for you to approve), or Open (anyone who can reach the server). Use Open only where you are happy for anyone to join.

After signing up, people see a QR code that connects their phone, and connection packages for each app.

Certificates

Devices connect with a certificate EdgeTAK issued when they were set up. This page lists them all.

  • Revoke a lost device's certificate: it is disconnected and can't connect again. The user's other devices keep working.
  • Server certificates shows when the CA, the server certificate and any Let's Encrypt certificate expire, and how each renews.
  • Device certificates are flagged before they expire (30 days by default); set how long new ones last here. A device renews by setting up again (a new QR code or package).

Data packages

Files shared through the server: what devices upload with ATAK's Send → Server, and what you upload here. Each is visible to its uploader's groups, unless you choose others.

  • Upload, search, download and delete packages.
  • Groups chooses which groups can see and download a package. When uploading here, you can choose them under Available to. Devices that already downloaded a package keep their copy.
  • Show on map draws a package's markers, routes, shapes and any KML, KMZ or GeoJSON on the console map.
  • To push a package to devices, use Send.

Missions (Data Sync)

Data Sync missions are shared workspaces: map items and files that every subscriber's device keeps in step, with changes pushed live. They are usually created in ATAK, WinTAK or iTAK (Data Sync); this page manages them.

  • See subscribers and their roles, the items and files, the change log and invitations.
  • Show on map draws a mission's items; Export downloads it.
  • A mission is visible to the groups it was created for. An event can make one for its group.

Maps: drawings and offline maps

Drawings

Draw markers, routes, areas and circles on the console map; they appear on devices' maps like items a teammate placed, for every device or chosen groups. Devices that were off get them when they connect; editing or deleting one updates devices.

Offline maps

  1. Make or get an MBTiles file of raster tiles (QGIS, MOBAC, gdal and the like).
  2. Upload it here, or copy large files into the server's maps folder (shown on the page) and Rescan the folder.
  3. It becomes a base map in the console, and ATAK devices get it as a map source when they connect, so maps work with no internet.

Your own tile sources (and ATAK map source .xml files) are under Map sources on the map itself; tick Send to ATAK devices to add one to devices' map lists.

Overlays

Send map overlays (boundaries, search sectors, routes, points) to devices without passing files around by hand.

  1. Import a KML, KMZ or GeoJSON file, name it, and pick the groups whose devices get it (none = every device).
  2. Connected devices get it straight away as one overlay in ATAK's Overlay Manager; devices that were off get it when they connect.
  3. Replace file sends a new version that replaces the old one; Stop sending pauses it.

ATAK can't be told to remove an overlay, so Delete only stops EdgeTAK sending it; people remove it on their device.

Plugins

An update server for ATAK, like tak.gov's: devices install and update plugins and apps from ATAK's Plugins screen.

  • Upload plugin or app APKs. Builds for several ATAK versions can sit side by side; each device gets the build for its version (or the nearest older one).
  • Devices are pointed at this update server automatically (Point devices at this update server).
  • If an app shows up as a plugin in ATAK (or the other way round), use Treat as app / Treat as plugin.
  • Plugins from tak.gov: link a tak.gov account, pick the ATAK version, and Add plugins without downloading them yourself.

Video

Video feeds for ATAK's and WinTAK's Video Player, limited by group.

  • Publishing: send a stream with any EdgeTAK username and password, e.g. rtsp://USER:PASSWORD@server:8554/NAME (RTMP and SRT work too). It appears on this page at once.
  • Save as feed names it, chooses who can watch and can give it a map position (a camera marker on devices).
  • Watching: on devices, open Video Player and import from the server; in the console, Watch.
  • Publishing without a login is for cameras that can't sign in: allow it only for named feeds.
  • Recording (off by default) keeps streams for a set number of days; play or download them under Recordings.
  • The MediaMTX card updates or restarts the video server.

Send

Send a chat message or a data package to everyone, chosen groups or chosen devices.

  • Pick the recipients, then write the message or choose a data package (including settings .pref packages).
  • Server contact: the server can appear on devices as an HQ contact; replies to its messages arrive in the Inbox.
  • Scheduled sends: a message or package at a set time, once or on a repeat (every few hours, daily, weekdays, chosen days).
  • Sent lists what went out.

Chat log

Off by default. When on, it records chat sent through the server (All Chat Rooms, team and group chats, one-to-one messages) for after-action reviews.

Search it, filter by conversation, sender and time, and export as CSV or JSON. How long messages are kept is set under Settings → Data retention.

Connecting devices

Ways to get a device onto the server, easiest first.

QR code (ATAK)

  1. On this page (or QR next to a user on Users), pick the user, how long the code works, and whether it's for one device.
  2. Make QR code and scan it with the phone's camera. ATAK opens and connects as that user. Nobody types a password.
  • With Let's Encrypt, ATAK enrolls with the code. On a local server, it downloads a connection package (over port 8080) with a certificate instead; use those codes on networks you trust.
  • The code is like a password until it expires: don't post it publicly. One device only codes stop 10 minutes after their first use.
  • Lost or new phone: tick New phone: replace their devices. When the new phone scans the code, the user's other devices are disconnected (you confirm first; nothing happens until the scan).
  • Print a QR sheet… makes a card per user for a briefing.
  • iTAK: choose iTAK under App. With Let's Encrypt, iTAK scans the code (Settings → Network → Servers → + → Scan QR) and signs in and enrolls by itself with the one-time code in it. On a local server, the iPhone's camera downloads a package instead, which you add in iTAK with Upload Server Package.

The code list

Updates live. Devices shows what each code set up: online with the callsign, offline, revoked, or never connected. If a phone that was already connected to this server as someone else scanned the code, restart ATAK. Revoke stops a code; Disconnect also cuts off the devices it set up.

Other ways

  • Connection package (any app): download it here and import it on the device. With a user picked it includes a certificate for them, so the app connects without a login (one per device; revoke it on Certificates). Without a user, ATAK, WinTAK and TAKX ask for a username and password and enroll. For iTAK choose iTAK.
  • Typing the address (servers with Let's Encrypt): add the server in the app, turn on Use authentication and Enroll for client certificate, and enter the username and password.
  • The sign-in page for users (link at the bottom) lets people get their own QR code and packages.

Also here

  • Position history: record devices' tracks (off by default) for trails, replay and KML/GPX export, from the map's History button.
  • Map sources: tile sources sent to devices' map lists.

Federation

Link this server with a TAK Server or another EdgeTAK, so devices on both see each other's positions, markers and chat, and get each other's data packages.

Connect to a TAK Server

  1. Connect to a server, enter its address and choose how to sign in: a certificate (port 9001; the TAK Server must trust EdgeTAK's CA, which Make the TAK Server trust EdgeTAK does with its admin login) or a federation token (port 9002).
  2. Its CA: Get it from the server, check the fingerprint with its admin, and trust it.
  3. Save. The list shows the connection's state and message counts.

Let other servers connect

Turn on Let other servers connect on port 9001. A server that connects waits under Waiting for approval; check its fingerprint, then Approve.

On a TAK Server with LDAP, give EdgeTAK's federate one of your users' groups (TAK Server groups for EdgeTAK), or no traffic crosses.

Settings

  • Emergency alerts: when someone presses ATAK's emergency button, every open console shows a red banner and sounds an alarm until acknowledged. The log is here.
  • Lost contact alerts: an amber alert with the last position when a device stops reporting (not when someone signs off on purpose). Untick to turn off.
  • Geofences: draw an area or circle and get an alert when devices enter or leave it.
  • Logo: Upload logo… puts your organization's logo in place of the ◆ mark on the console, the sign-in, sign-up and account pages and printed QR sheets, and makes the browser tab and installed-app icons from it. PNG, JPEG or WebP; Remove brings back the default.
  • Plain TCP: turn port 8087 (unencrypted, anonymous devices that only see __ANON__) on or off without a restart. Turning it off closes the port and disconnects those devices. If the server has a firewall, open 8087 there too (sudo ufw allow 8087/tcp).
  • Let's Encrypt: enter a domain name whose DNS record points at this server (and optionally an email address), then Turn on. EdgeTAK restarts and requests a Let's Encrypt certificate for the enrollment port (8446), so apps can quick-connect with just the address, a username and a password. Port 80 must be open to the internet, in the server's firewall and the cloud provider's. The domain becomes the public host; connection packages and QR codes made before keep the old address. Turn off goes back to the EdgeTAK certificate.
  • Mesh bridge: connects ATAK's mesh (devices sharing positions and chat over multicast on Wi-Fi or MANET radios, without a server) to EdgeTAK. Tick the interface the radios are on, choose the group what's heard goes to and the groups sent back, and what to send (positions, chat, emergencies, drawings). Radio teams and server users then see each other, and radios can send direct chat to server users.
  • ZeroTier: put the server on a ZeroTier network so devices anywhere reach it without opening router ports. Install ZeroTier, join your network by its ID, then authorize this server's node in ZeroTier Central. Use for devices next to its ZeroTier address makes the Connect page's packages and QR codes point there.
  • Remote access (FRP): reach the server from anywhere without opening router ports. You need an FRP server (frps) on a VPS or a relay service. Set up remote access, paste or load its frpc.toml (or Start from a template and fill in the server and token), save and Connect. EdgeTAK downloads frpc and keeps it running. Use for devices points packages and QR codes at the FRP server.
  • Aircraft and ships: live aircraft (ADS-B, from adsb.lol, adsb.fi, or a custom URL: your own receiver's aircraft.json or another API, with its API key in a header or the URL) and ships (AIS, from aisstream.io with a free API key) around an area, sent to devices as map markers. Set the center (or Use the map's center), then for each feed its radius, whether to send it and to which groups. They also show on the console map as the Aircraft and Ships layers.
  • Login protection: blocks an address after too many wrong passwords. Add your own networks to Never block, and unblock people here.
  • Data retention: how long to keep packages, missions, messages, the chat log and the audit log. It shows what would be removed before you save.
  • Backup and restore: download a backup (or schedule them) and restore one onto this or a new server.

Webhooks

Send alerts to Discord, Slack, Microsoft Teams, ntfy (phone notifications) or any URL, so people hear about them with the console closed.

  1. Get a webhook URL from the service (the page has the steps for each).
  2. Add webhook, choose the service, paste the URL and choose the alerts: emergencies, geofences, lost contact, sign-ups, admin changes, server health, blocked sign-ins.
  3. Save and press Send test.

Limit a webhook to groups to hear only about those users' devices.

API keys

Tokens for scripts and automations (Grafana, Home Assistant, your own scripts) to use EdgeTAK's REST API without a person's password or two-factor login.

  1. Give the key a name, choose the user it acts as, and optionally make it read-only or expire after some days.
  2. Make key and copy it right away: it is shown only once.
  3. Send it over HTTPS as Authorization: Bearer etk_…, for example curl -H "Authorization: Bearer etk_…" https://your-server:8443/admin/api/status.
  • A key can do whatever its user can: everything, for an administrator. A read-only key can only read.
  • It stops working when you delete it, when it expires, or when its user is deleted or disabled.
  • The list shows when and from where each key was last used, and the audit log names the key behind each change.

Extensions

Server plugins that add features to EdgeTAK, such as tracker or radio bridges, exports and integrations. An extension is a program (a .zip with a plugin.json) that EdgeTAK runs and keeps running.

  1. Install extension… and choose the .zip. Installing a newer version of an installed extension updates it and keeps its data.
  2. Check what it may do: receive CoT, send CoT, read server data (groups, devices, missions, position history), or show a page here.
  3. Choose the groups it receives CoT from and sends CoT to. They work like a user's groups.
  4. Start it. EdgeTAK starts it again if it stops, and when EdgeTAK starts.
  • Open page shows its page, for its settings. Log shows what it printed, the first place to look when it misbehaves.
  • It runs on the server like any other program, so only install extensions you trust.
  • To write one, see the extension guide.

Audit log

Every change an administrator makes, with who, from where, what and whether it worked; also sign-ins, failed sign-ins, blocked addresses, device enrollments and QR codes used. Passwords and keys are never recorded.

Search it, show failures only, and download it as CSV. How long it is kept is under Settings → Data retention (forever by default).

Clear log… deletes every entry after you confirm; download a CSV first if you need them. The clearing itself stays as the first entry of the new log.

Simulator

Load testing: simulated devices connect like ATAK, move around and send positions (and chat), so you can see how the server copes before a big event.

  • Choose how many devices, how fast they join, how often they report and how long to run, then watch connections, events per second, relay time, CPU and memory live.
  • They use a temporary account in the Simulator group, so real devices don't see them; it is removed when the run ends.
  • Traffic grows with the square of the devices; start small on a Raspberry Pi. Turn position history off first if you don't want them recorded.

My account and two-factor login

Everyone signs in at the same page: administrators go on to this console, users to their account page, where they get a QR code for their phone and connection packages, see their devices and certificates, revoke a lost device's certificate, and change their password.

Two-factor login (optional): turn it on from the account page (or for yourself, on Users), scan the code with an authenticator app, and keep the recovery codes. TAK apps keep using the password. If someone loses their phone, an admin can Reset 2FA on Users.

Troubleshooting

  • A device can't connect: check Public host on the Dashboard is an address the phone can reach, and that the ports are open (8089 for devices, 8443 for the API, 8446 for setting up). Is the user disabled, or the certificate revoked?
  • A QR code shows "never connected": the phone was probably already connected to this server as someone else. Restart ATAK (or remove the server in ATAK and scan again).
  • Devices don't see each other: they need a group in common (in on one side, out on the other). Check Groups on each user.
  • Someone is locked out: see Blocked now under Settings → Login protection.
  • See what a device is doing: set log_level to debug and watch the server log (journalctl -u edgetak -f); every request is listed.
  • The full manual is the README on GitHub.
